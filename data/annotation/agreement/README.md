# Second-annotator check

Two sheets for the second annotator, generated by
`uv run python scripts/data/agreement.py sample` (fixed seed; do not regenerate
once annotation has started). Open them in LibreOffice Calc or Excel; they are
UTF-8 CSV, and must be saved back as CSV (UTF-8, comma-separated).

## 1. `lemma_sheet.csv` (200 words, about 1–2 hours)

Write the lemma of each word in the `lemma` column, following
`docs/annotation_guidelines.md`. The words are frequent Tamil Wikipedia forms,
in random order. Work independently: do not look up the first annotator's file.
`pos` and `note` are optional.

The two annotations are then compared with
`uv run python scripts/data/agreement.py score`, which reports the share of
words where both gave the same lemma (and Cohen's kappa for the decision
whether a word is reduced at all) in `bench/results/m3_expansion/agreement.csv`.

## 2. `error_examples_sheet.csv` (15 rows, about 15 minutes)

Each row is a word our model lemmatized wrongly: the word, the treebank's
`gold_lemma`, the outputs of the two models, and the error `category` that a
program assigned automatically. For each row:

- `category_ok`: `y` if the category describes the mistake, else `n`, and in
  `better_category` write a better description;
- `gold_ok`: `y` if the treebank's gold lemma is correct, else `n`, and write the
  correct lemma in `correct_lemma`.

Categories: Form left unchanged · Gold keeps the form (the treebank keeps the
word as it is, the model reduced it) · Suffix partly left · Too much removed ·
Stem-final letter wrong · Other / wrong stem.
